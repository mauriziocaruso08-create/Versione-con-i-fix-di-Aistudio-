# MAIA V6.5 — Context Continuity Hardening

## Scope
Stabilization only. Existing UI, persistent storage, MAIA Core and provider architecture preserved.

## Fixes

### 1. Active selection now has priority for pronoun follow-ups
When the user explicitly selects an item, that selection is now authoritative for the next contextual pronoun action.

Examples:
- "Mostrami le note" → "la seconda" → "modifica questa"
- "Mostrami i promemoria" → "il secondo" → "spostalo a domani"

Older entries in `recentReferences` can no longer incorrectly turn an already-selected item into an ambiguity.

### 2. Stale selections are rejected
A selected item is resolved only if its ID still exists in the authoritative Notes/Reminders store. Deleted items can no longer be resurrected by conversational context.

### 3. Session TTL is now consistent
`TargetResolver` now uses the configurable SessionContext TTL instead of a hard-coded five-minute constant. Test/configuration TTL values therefore apply consistently across the whole contextual resolution pipeline.

### 4. Displayed-item ordinals are re-indexed
Whenever the displayed collection is refreshed, indexes are normalized to `1..N`. This prevents stale ordinal references after deletion, filtering or list updates.

## Regression coverage
Added `test_context_continuity_hardening.ts` covering:
1. selected-item priority over multiple recent references;
2. rejection of a stale/deleted selected item;
3. custom SessionContext TTL enforcement.

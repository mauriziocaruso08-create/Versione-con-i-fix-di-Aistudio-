# MAIA V7.1 — Roadmap Integration v3

This package combines the three open bug fixes with a low-risk roadmap slice.

## Fixed
- Persistent profile identity is mirrored to `maia_user_profile_v1`, independent from chat history. Transient empty memory state can no longer overwrite a valid stored name/city; explicit memory deletion still clears the profile.
- Generic `Cancella il promemoria` is unresolved when no explicit target/all scope is stated.
- Note listings preserve and display title + content.

## Roadmap slice added
- Model Router automatic failover across configured real providers.
- Provider/Budget status remains exposed through `/api/status`.
- Regression checklist for Context, Intent, Target Resolution, Clarification, Verification and persistence boundaries.

## Projects roadmap slice — isolated data foundation
- Added `src/services/projects/projectManager.ts` with a dedicated `maia_projects_v1` store.
- Project records have name, objective, context, status, notes, and timestamps.
- CRUD operations verify persisted writes and reject empty/duplicate project names.
- This store does not read or write `maia_user_memory_v1` or the legacy `UserMemory.projects` array. Existing personal-memory behavior remains unchanged.
- Added `test_project_manager.ts` to cover persistence, isolation, duplicate rejection, note preservation, update/delete behavior, and corrupted storage handling. The isolated test and strict TypeScript compilation passed in the authoring environment; the full project regression suite and UI integration remain pending validation in Termux.

## Deliberately deferred
- Native Android integrations, camera/screen sharing, contacts/calendar/calls.
- Monetization.
- Manual verification of Projects UI behavior, mobile layout, and persistence after app/browser restart remains pending. The dedicated project store is intentionally separate from legacy personal memory.

## Projects UI integration candidate — 2026-10-12
- The existing Settings > Progetti category now reads and writes `maia_projects_v1` through `projectManager`, instead of treating projects as strings in `UserMemory.projects`.
- UI supports create, edit metadata, update status, add project notes, and delete projects. The general “clear personal memory” action does not clear the separate project store.
- UI interactions are not covered by the Node regression harness; run lint, production build, full regression, and manual Preview checks before treating this candidate as validated.

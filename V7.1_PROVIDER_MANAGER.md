# MAIA V7.1 — Provider Manager Hardening

This step begins the next roadmap block without changing the MAIA Core pipeline.

## Implemented
- Central `ProviderManager` registry.
- Provider priority for automatic routing.
- Provider availability/configuration filtering.
- Optional allow-list through `MAIA_AI_ALLOWED_PROVIDERS`.
- `ModelRouter` now delegates provider discovery/selection to the manager.
- Existing Gemini/mock behavior remains compatible.

## Intentional scope
No new external provider is enabled by this step. OpenAI/Claude/Mistral/local providers can be registered later through the same `AiProvider` contract.

## AI Budget / Quota policy implemented
- `AiBudgetManager` now guards model requests before provider execution.
- Optional global daily request limit via `MAIA_AI_MAX_REQUESTS_PER_DAY`.
- Optional per-provider daily limits via `MAIA_AI_MAX_REQUESTS_<PROVIDER>_PER_DAY` (for example `MAIA_AI_MAX_REQUESTS_GEMINI_PER_DAY`).
- `0` or an omitted limit means unlimited.
- Limits are enforced only after the Core has selected a provider; local capabilities are unaffected.
- Successful provider calls are counted; failed calls are not consumed as successful requests.
- No artificial token/cost estimate is introduced yet; provider-specific accounting remains a later step.

## Next roadmap step
Add provider-specific cost metadata and explicit paid-provider authorization before enabling multiple paid providers automatically.

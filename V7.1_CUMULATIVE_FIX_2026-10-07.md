# MAIA V7.1 — Cumulative Fix 2026-10-07

## Test cycle

This patch is based on the V7.1 Intent Understanding 2 + Personal Memory Hardening baseline tested in AI Studio.

### Confirmed functional regressions

- Note creation with title + content: PASS.
- Note listing with title + content: PASS.
- Note contextual/explicit update: FAIL before patch.
- Reminder create/list/update: PASS.
- Reminder contextual target, ambiguity and pending clarification: PASS.
- Destructive note/reminder confirmation: prompt PASS; confirmation execution was not reliably preserved when the runtime was interrupted.
- Reset Chat History persistence: PASS.
- Clear Memory isolation and verification: PASS.
- Local reminder listing did not consume AI budget: PASS.
- Natural reminder formulation `Spostami quello di comprare il pane a venerdì alle 20`: blocked before patch.
- English local read `Which reminders do I have?`: blocked before patch.
- Personal Facts were not counted/displayed as a first-class Memory category in Settings: FAIL.
- AI budget UI did not refresh after a successful generative request: observed as 0 during the test.
- HTML-as-JSON errors were observed when the AI Studio runtime/API returned an HTML page instead of JSON.

## Root causes addressed

### 1. Destructive confirmation recovery
Pending confirmations were RAM-only. If Preview/runtime state was interrupted, a following `Sì` could be interpreted as a normal conversational request and reach Gemini.

**Fix:** safety-critical pending confirmation is mirrored to `localStorage` with the existing 2-minute TTL. If no in-memory confirmation exists, the resolver restores the persisted one. A standalone confirmation token with no pending operation is handled locally and never falls through to Gemini.

### 2. Note target resolution
Target matching only searched note text. A note title such as `Spesa` therefore could not be resolved by title.

**Fix:** target resolution searches both `title` and `text` for notes and reports a title-aware match.

### 3. Note/reminder append semantics
The parser treated `aggiungi` as part of the target or failed to identify it as an update operation.

**Fix:** update intents now carry `updateMode: APPEND | REPLACE`. Natural forms such as `Aggiungi alla nota ...` and `... e aggiungi ...` are mapped to the same UPDATE pipeline. Capabilities verify the final stored text.

### 4. Natural local intent coverage
`Spostami ...` was not recognized by the contextual UPDATE entry point.

**Fix:** semantic handling accepts the grammatical variant without adding a phrase-specific action handler.

### 5. English local intent bridge
`Which reminders do I have?` did not enter the local pipeline.

**Fix:** common English semantic concepts are normalized into the existing intent pipeline. This is a language bridge, not a separate command implementation.

### 6. JSON transport hardening
`response.json()` was called without checking the response content type. If AI Studio/Vite returned HTML, the UI surfaced `Unexpected token '<'`.

**Fix:** MAIA Core validates JSON content type and emits a controlled error when the server returns HTML/non-JSON. The initial `/api/status` call is hardened similarly.

### 7. AI budget UI freshness
The server consumed the budget internally but successful `/api/chat` responses did not return the updated router status, so Settings could continue showing stale counters.

**Fix:** successful chat responses now include `modelRouter` status and the frontend refreshes the displayed status after a generation.

### 8. Personal Facts in Memory UI
Personal Facts were persisted and queryable but were not included in the Settings Memory count/category.

**Fix:** `Informazioni personali` is now a first-class Memory category and its items contribute to the memory count.

## Deliberately NOT classified as MAIA Core bugs

The following were observed in AI Studio but are not automatically treated as MAIA logic defects:

- `App has been paused`
- AI Studio switching to Chat/Preview autonomously
- `ais-dev-...run.app unexpectedly closed the connection`
- `4 errors running the code`

They remain **Runtime / AI Studio environment evidence**. The JSON hardening above reduces the user-visible failure when the backend responds incorrectly, but the AI Studio runtime itself must be investigated separately if the behavior persists.

## Verification rule

No success response should be emitted for a mutating operation unless the capability verifies the postcondition. Gemini remains a conversational provider; MAIA Core remains the authority for local state and action completion.


## V7.1 Next Cumulative Patch — Intent/Memory Hardening

Confirmed by torture testing 2026-10-07:
- natural Italian note/reminder creation must remain local;
- English local intents must normalize into the same semantic pipeline;
- contextual English follow-ups must preserve SessionContext;
- negative local destructive requests must never reach Gemini;
- composed confirmations such as `Sì, elimina.` and `Sì, confermo.` must resolve the pending confirmation locally;
- selective personal-fact deletion must be Core-owned;
- Clear Memory must clear UserMemory, profile, notes and reminders;
- note/reminder append uses `; ` as separator;
- note titles participate in target/context resolution.

AI Router & Budget was regression-tested separately and showed correct local-vs-generative routing and request counting; no direct router/budget change is included here.
